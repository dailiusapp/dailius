# Dailius UI Design System

## Purpose

This document defines the visual and interaction guidelines for Dailius.

The goal is to create a product experience that feels:

- Calm
- Intelligent
- Personal
- Trustworthy
- Simple

Dailius should feel like a personal assistant, not another productivity tool.

---

# Brand Personality

Dailius is:

- Thoughtful
- Encouraging
- Organized
- Human
- Professional

Avoid:

- Overly corporate design
- Aggressive productivity messaging
- Gamification
- Clutter
- Information overload

The product should help users feel in control of their time.

---

# Visual Principles

## Simplicity First

The user should immediately understand:

- What is happening today
- What matters next
- Why something was scheduled

Avoid showing unnecessary complexity.

---

## Calm Interface

Use whitespace intentionally.

Do not create dashboards full of metrics unless they directly help decision-making.

---

## AI Should Feel Present but Not Intrusive

The AI should feel like a helpful assistant.

Good:

"Your long ride was moved to Saturday because you have more recovery time available."

Avoid:

"Optimization complete. Efficiency increased by 14%."

---

# Color System

## Primary Brand

Use the official Dailius brand colors.

The AI highlight color should match the Dailius logo/fav icon.

---

## Semantic Colors

Success:

Used for:

- Completed activities
- Positive outcomes

Warning:

Used for:

- Conflicts
- Attention needed

Error:

Used for:

- Failed actions
- Validation errors

Info:

Used for:

- AI explanations
- Suggestions

---

# Typography

Use a clean modern sans-serif font.

Priorities:

- Excellent readability
- Clear hierarchy
- Friendly appearance

Typography hierarchy:

## Heading

Used for:

- Page titles
- Major sections

## Subheading

Used for:

- Feature sections
- Cards

## Body

Used for:

- Explanations
- Descriptions

## Small Text

Used sparingly for:

- Metadata
- Secondary information

---

# Layout Principles

## Spacing

Prefer generous spacing.

The interface should not feel crowded.

---

## Cards

Cards should represent meaningful concepts.

Examples:

Good cards:

- Weekly plan
- Goal
- Activity
- AI recommendation

Avoid excessive card nesting.

---

# Core Components

## Buttons

Primary:

Used for main actions.

Examples:

- Generate Plan
- Save Changes
- Continue

Secondary:

Used for alternatives.

Examples:

- Cancel
- Edit
- View Details

---

## Forms

Forms should:

- Ask one concept at a time
- Provide examples
- Avoid overwhelming users

Prefer onboarding conversations over long forms.

---

## Calendar View

The calendar is not the product.

It is the visualization of the AI plan.

Prioritize:

- Clarity
- Balance
- Understanding

Over:

- Dense scheduling controls

---

# Empty States

Every empty state should answer:

1. What is missing?
2. Why does it matter?
3. What should the user do next?

Example:

"No activities yet.

Tell Dailius what matters to you and we'll help find time for it."

---

# Loading States

Avoid generic loading messages.

Prefer:

"Creating your weekly plan..."

"Finding the best time for your workouts..."

---

# Responsive Design

The MVP should support:

- Desktop
- Tablet
- Mobile browser

Native mobile apps are not part of MVP.

---

# Design Rules

Before adding a UI element ask:

Does this help the user understand or improve their plan?

If not, remove it.
